# 앱개발
- 가장 중요한 원칙: 지적·메모를 글자 그대로 그 한 곳만 고치지 말 것. 왜 그런 말을 했는지 이유를 생각하고, 같은 문제가 있는 곳을 초안 전체에서 찾아 같이 고칠 것.
- 사용자 불만(11/23~24): 고친 게 대부분 자기가 말한 것뿐. 검토 AI는 사용자가 준 기준 목록에만 맞추지 말고 전반적으로 전부 볼 것(실제 디자이너·실사용자 눈). 모든 화면을 국내 앱(당근·네이버·카카오톡·토스·왓챠피디아·오늘의집·비트윈·소모임)과 나란히 놓고 레이아웃·여백·줄 높이·글자·색·아이콘·버튼까지 비교(11/24: 줄 높이 과다를 못 찾은 이유 = 실제 앱과 비교 안 하고 자체 규칙만 맞춤). 보고 시 "먼저 찾아서 고친 것"을 따로. 디자인 세부는 사용자에게 묻지 말고 AI끼리 정해서 고친 뒤 결과만 보고(사용자가 정한 걸 바꿀 때만 질문).
- 목표: 보드게임 앱. 전체 보드게임 데이터 수집, 플레이 기록(누구와·날짜), 평가 작성 및 공개 공유, 평가가 게임 화면에 달림, 보유 게임 보관함.
- 핵심: 기록 앱. 기록을 쉽게 쓰고 쉽게 확인하는 게 메인(홈도 이 기준).
- 디자인·문구: AI스럽지 않게, 실제 국내 앱 참고. 항상 실제 이용자 입장. 한 화면에 기능을 몰아넣지 말 것(화면마다 목적 하나, 탭으로 나누기). "나" 대신 닉네임 표시(긴 닉네임도 안 깨지게). 특히 보관함은 더 예쁘게. 커플은 예쁘게 꾸미기(색 통일 규칙은 사용자가 말한 적 없음). 뜻이 바로 안 와닿는 문구 금지.
- 작업 방식: 빠진 기능은 먼저 한 번에 정리해 제안. 디자인 검토·구성 검토·이용자 관점(커플·모임 기록 담당·일반 멤버·혼자·처음 사용자) 검토 AI를 쉬게 두지 말 것. 보여주기 전 폰 크기 확인. 수정은 사이트(https://arkeun.github.io/arkeun/)에 반영하고, 보고 시 사진 말고 캐시 피하려 ?v=값 붙인 링크 + "어디를 눌러 뭘 해 보면 되는지" 순서를 줄 것.
- 규모 기본 가정: 모임 수백 개, 모임 안 게임 수백 개, 멤버 수십~수백 명, 기록 수천 판(하루 한 게임 수십 판 포함), 보관함·즐겨찾기 수백 개, 댓글·알림 수백 개.
- 플랫폼: 개발 단계는 웹페이지, 이후 아이폰·안드로이드 둘 다 출시.
- 데이터: BGG 기준, 자동 수집, 설명은 한글 자동 번역 제안. BGG 앱 등록 필요(사용자 토큰 대기).
- 기록: 하루 단위로 묶고, 여러 게임·여러 판, 판마다 승자/순위(공동 가능), 점수·메모·사진·영상은 선택. 승리 조건: 높은 점수·낮은 점수·임의. 게임/판마다 멤버 다를 수 있음. 자정 지나면 그 날짜. 장소 항목 없음. 확장은 본판에 붙여 판마다 여러 개 선택. 즐겨찾기 필요. 시간·"몇 판" 같은 숫자는 기록장에서 빼고 통계 탭에만.
- 연동: 기록한 사람만 수정. 친구에겐 알림만, 무시해도 기록됨, 원치 않으면 본인이 뺌. 앱 없는 친구는 연결 후부터 연동, 지난 기록은 기록한 사람이 직접 친구로 바꿈(이름 같다고 자동 연결 금지).
- 사람 고르기: 검색창 하나에서 앱 친구·앱 사용자·앱 없는 친구 모두 처리. 모임·커플이 즐겨찾기처럼 묶여 뜸. 캐릭터 꾸미기.
- 모임: 게임별 승수·승률, 연말 축하. 순위는 판마다 1승. 11/24 챗GPT 설계 승인 → 모임 찾기·게시판·일정(가입과 참석 분리)·운영진, 기록 시 모임 기본값 '모임 없음'.
- 커플: 별도 공간(홈·같이 할 게임·기록·통계). 같이 할 게임 = 하트 찜(상대 찜 확인·알림), 커플 사진은 각자 한 장씩 넣어 반반 합침.
- 게임 화면: 정보·평가·질문 탭. 평가: BGG 방식 10점 + 난이도 1~5, BGG 평균과 앱 평균 나란히. 댓글 가능.
- 홈: 리스트형/달력형 선택(리스트 기본). 한 달씩 "< 2026년 11월 >" 좌우로 넘김(아래로 쌓지 않음). 달력 칸에는 누구랑 했는지(모임명 / 상대♥ / "현우 외 2명" / 혼자). 탭: 홈 · 보관함 · 기록 · 모임 · MY.
